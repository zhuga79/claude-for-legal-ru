# claude-for-legal-ru

Набор плагинов Claude Code для юридической работы по праву РФ. Форк
[anthropic/claude-for-legal](https://github.com/anthropic-experimental/claude-for-legal),
переработанный под российское право: не перевод, а замена правового существа.

> **Это не юридическая консультация.** Каждый вывод любого скилла — **проект для проверки
> практикующим юристом**. Подавать в суд, подписывать и сдавать в государственный орган
> подготовленное здесь можно только после проверки человеком.

---

## Установка

```bash
claude plugin marketplace add /путь/к/claude-for-legal-ru
claude plugin install dogovornoe-pravo@claude-for-legal-ru
```

Плагины ставятся по одному — берите только те контуры, в которых работаете. Плагин
`vedenie-del` подтягивается автоматически как зависимость: он ведёт общий портфель дел,
чтобы одно дело клиента не разваливалось на несколько при переходе от договорного вопроса
к спору или корпоративному.

После установки запустите cold-start-интервью нужного плагина — до заполнения профиля
скиллы останавливаются и просят настройку:

```
/dogovornoe-pravo:cold-start-interview
```

> **Правка плагина не доезжает до среды сама.** Кэш версионный:
> `~/.claude/plugins/cache/<маркетплейс>/<плагин>/<версия>/`. После изменения файлов нужен
> `claude plugin uninstall <плагин> --keep-data` и повторный `install`; `claude plugin update`
> при неизменной версии отвечает «already at the latest version» и ничего не делает.

## Как это устроено

**Профиль вместо универсальных ответов.** У каждого плагина есть `CLAUDE.md` — профиль
практики, который заполняется на cold-start и лежит в
`~/.claude/plugins/config/claude-for-legal-ru/<плагин>/CLAUDE.md`. Вывод зависит от того,
на чьей вы стороне, какая у клиента организационно-правовая форма и какой у вас статус.
Общий профиль организации — уровнем выше, `company-profile.md`
(шаблон — `company-profile.template.md` в этом репозитории).

**Гейты вместо оговорок.** Скилл не выдаёт вывод «с оговоркой», если задача вне его области.
Он останавливается: корпоративный плагин останавливается на некоммерческой организации,
плагин НКО — на видах, кроме АНО и фонда, абхазский — на российском юрлице и наоборот.
Организационно-правовая форма и юрисдикция определяются **до** применения норм.

**Разграничение ролей.** Правовые скиллы не считают налоги. Там, где структура сделки меняет
налоговый результат — вход инвестора, переквалификация ГПХ, поступления в НКО, — скилл
называет развилку и передаёт вопрос налоговому специалисту, вместо того чтобы дать
правдоподобный ответ вне своей роли.

**Currency-watch.** У плагинов в быстро меняющихся зонах есть `references/currency-watch.md`:
перечень тем повышенной изменчивости с датой последней сверки и протоколом устаревания.
Старше 90 дней — файл считается списком тем для поиска, а не источником статуса, и скилл
обязан сказать об этом прямо.

**Пометки о происхождении.** `[сверено ДД.ММ.ГГГГ]`, `[проверить по первоисточнику]`,
`[знания модели — проверить]` — тег говорит о происхождении сведения, а не об уверенности.
Пометки не украшение: самый опасный дефект в этой области — не выдуманная норма, которую
видно, а **норма в устаревшей редакции**, которая внутренне непротиворечива и потому
вычиткой не ловится.

## Статус

Проект в работе. Правовое существо каждого плагина проходит ревью роли `lawyer` или
`compliance`, а затем — независимое ревью другой моделью другого провайдера, чтобы не получить
коррелированные слепые пятна: одна и та же модель, проверяя себя, вносит ошибки в те же абзацы,
которые правит.

**Не всё прошло обе стадии.** Что закрыто, что нет и какие места помечены как непроверенные —
в `TASKS.md`; решения и их основания — в `LOG.md`; правила работы — в `BRAIN.md`.
Перед опорой на конкретный скилл посмотрите, какой у него статус.
