# Структура дела

Корень: `~/.claude/plugins/config/claude-for-legal-ru/dela/`

Реестр — машинная истина по статусу и срокам. Папка дела — носитель текста. Даты живут **только
в реестре**; карточка на них ссылается и не дублирует, иначе они разойдутся.

## `_sostoyanie.md`

```markdown
# Ведение дел

Включено: ✗
Активное дело: —
Кросс-контекст: выкл
Корень дел: по умолчанию

<!--
Включено ✗ — нормальное состояние для инхауса с одним работодателем.
Кросс-контекст «вкл» разрешает скиллам читать файлы других дел. По умолчанию выключен.
Корень дел не должен указывать в примонтированное облако — ч. 5 ст. 18 ФЗ-152.
-->
```

## `_reestr.yaml`

```yaml
dela:
  - slug: postavka-alfa
    klient: "ООО «Ромашка» (внутренний заказчик: отдел закупок)"
    drugaya_storona: "ООО «Альфа»"
    sut: "Поставка оборудования, спор о качестве"
    tip: dogovornoe          # dogovornoe | pdn | spor | inoe
    vedet: "Иванов И. И."
    sozdano: 2026-08-07
    status: v_rabote         # v_rabote | priostanovleno | zakryto
    hranit_do: null          # заполняется при закрытии
    peresmotr: null          # дата пересмотра необходимости хранения
    sroki: []
```

### Схема срока

```yaml
    sroki:
      - vid: obzhalovanie       # zasedanie | processualnyj | materialnyj | vnutrennij
        sobytie: "изготовлено решение в полном объёме"
        ot: 2026-03-12
        ischislenie: mesyacev   # kalendarnye_dni | rabochie_dni | mesyacev
        dlitelnost: 1
        istekaet: 2026-04-13
        norma: "ч. 1 ст. 259 АПК [проверить]"
        vosstanovim: true       # ст. 117 АПК / ст. 112 ГПК [проверить]
        status: aktiven         # aktiven | ispolnen | propushchen
        ischislil: agent        # agent | polzovatel
        proveril: null          # ФИО и дата; null = расчёт человеком не подтверждён
```

**Кто заполняет.** Строку срока пишет профильный плагин, который умеет исчислять срок по норме.
Каркас строку принимает, хранит, сортирует и показывает. Каркас **не вычисляет** `istekaet` и не
переносит дату с нерабочего дня — это правовое существо.

**Почему `ischislil` и `proveril` обязательны.** Сводка сроков выглядит авторитетно независимо от
того, кто её посчитал. Пока `proveril` пуст, вывод сопровождается пометкой
`[расчёт не подтверждён человеком]`. Цена ошибки — утрата процессуального права.

## `delo.md`

```markdown
# Дело: <название>

Клиент: <кто>
Другая сторона: <кто>
Суть: <одно предложение>
Тип: <договорное / ПДн / спор / иное>
Ведёт: <кто>
Заведено: <дата>
Статус: <в работе / приостановлено / закрыто>

## Что важно по этому делу

<Переопределения профиля практики: позиции, отличные от стандартных, согласованные уступки,
красные линии именно этого дела. Пусто — значит применяется общий плейбук.>

## Сроки

Ведутся в `_reestr.yaml` (см. `spisok`). Здесь не дублировать.

## Материалы

- `dokumenty/` — исходники
- `vyvody/` — выводы скиллов
```

## `zhurnal.md`

```markdown
# Журнал: <название дела>

## 2026-08-07 | заведено дело
Первичные обстоятельства, кто передал, что просили.
```

Только добавление, новое сверху. Прошлые записи не переписывать: журнал — источник хронологии,
а хронология в споре имеет доказательственное значение.

## Именование

`slug` — латиницей, через дефис, без ФИО и без иных персональных данных: имя папки видно в путях,
логах и подсказках. `postavka-alfa`, а не `ivanov-razvod`.
