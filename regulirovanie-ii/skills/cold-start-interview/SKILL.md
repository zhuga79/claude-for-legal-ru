# /regulirovanie-ii:cold-start-interview

## Назначение

Заполнить `~/.claude/plugins/config/claude-for-legal-ru/regulirovanie-ii/CLAUDE.md` фактами
организации. До этого работает только этот скилл.

## Контекст дела

Прочитай (если уже есть) `~/.claude/plugins/config/claude-for-legal-ru/company-profile.md` — общий
профиль форка. Если его нет, предложи после этого интервью запустить настройку уровнем выше
(не обязательно сейчас).

## Ход интервью

Задавай по разделам, не всё одним сообщением. После каждого раздела — короткое резюме на
подтверждение.

### Шаг 1. Кто мы

- Тип организации, зрелость по ИИ (изучаем / пилотируем / продакшен / масштабировано)
- Ответственный за ИИ в организации (ФИО/должность — это организационная роль, не статус,
  предусмотренный законом)

### Шаг 2. Разработчик или пользователь ИИ

**Ключевой развилочный вопрос:** организация сама разрабатывает/обучает/дообучает большую
фундаментальную модель ИИ (≥ 1 млрд параметров — определение ФЗ от 26.07.2026 № 243-ФЗ), или
только использует чужие модели и сервисы (API, встроенный ассистент в SaaS)?

> Разработчиков 243-ФЗ касается почти целиком (обязанности по безопасности, документации, статус
> «суверенная»/«национальная» модель — с 01.03.2027). Пользователей чужих моделей — в основном
> обязанность уведомить своих пользователей о правах на результаты генерации, если организация сама
> даёт доступ к нейросети конечным пользователям (тоже с 01.03.2027). `[веб-поиск 2026-08 — закон не
> вступил в силу на дату форка, сверяй сроки и состав обязанностей по первоисточнику]`

Если организация — оператор интернет-платформы с личными страницами пользователей и аудиторией
от 500 тыс. пользователей из РФ в сутки — отметь отдельно: для таких платформ 243-ФЗ добавляет
обязанность обеспечить техническую возможность маркировки ИИ-контента (с 01.03.2027).

### Шаг 3. Текущие AI-системы (черновой список, детали — в `reestr-sistem-ii`)

- LLM-сервисы: зарубежные / российские / self-hosted open-source
- Классическое ML / CV / иное
- Для каждой крупной системы — обрабатывает ли ПДн (если да — доуточнение позже через
  `personalnye-dannye`, этот плагин не переспрашивает то, что там уже есть)

### Шаг 4. Регуляторный контекст

- 152-ФЗ — есть ли AI-системы, обрабатывающие ПДн? Если да, работает ли уже `personalnye-dannye`
  этого форка? Если ещё не настроен — скажи прямо: без него AI-специфичный слой неполон.
- Отраслевое регулирование: финансовое / медицинское / образовательное / гос.услуги
- Участие в экспериментальном правовом режиме (123-ФЗ Москва или иной регион по ФЗ-258)
- Подписан ли добровольный Кодекс этики в сфере ИИ (2021, Альянс в сфере ИИ) — уточни: это не
  создаёт юридической обязанности, спрашиваем для полноты картины позиционирования организации

### Шаг 5. Санкционная экспозиция

- Какие зарубежные AI-сервисы недоступны/ограничены
- Работа через VPN/прокси — как факт бизнес-риска, не как предмет правового вывода
- Планы/факт перехода на российские или self-hosted альтернативы

### Шаг 6. Обучающие данные (только если разработчик по шагу 2)

- Источники (внутренние / публичные / закупленные / пользовательский контент)
- ПДн в обучающих данных и правовое основание
- Собираются ли опираться на исключение 243-ФЗ для обучения на общедоступных объектах авторского
  права без согласия правообладателя (действует только для суверенных/национальных моделей)

### Шаг 7. Внутренняя политика ИИ

- Утверждена ли, кем, дата
- Процесс одобрения новых сценариев использования
- Комитет/ответственный по этике ИИ (если применимо)

### Шаг 8. Аппетит к риску

Консервативный / средний / агрессивный + что организация никогда не делает с ИИ.

### Шаг 9. Сохранение

Запиши всё в CLAUDE.md плагина по пути из шапки файла (создай папки при необходимости). Не
переписывай общий company-profile.md — это другой уровень.

```
✓ CLAUDE.md плагина regulirovanie-ii сохранён.

Доступные скиллы:
- /regulirovanie-ii:reestr-sistem-ii — инвентаризация AI-систем организации
- /regulirovanie-ii:proverka-postavshchika-ii — проверка договора с AI-поставщиком (поверх
  dogovornoe-pravo:vendor-agreement-review)
- /regulirovanie-ii:proverka-obuchayushchih-dannyh — проверка обучающих данных (152-ФЗ + часть 4 ГК,
  исключение 243-ФЗ для суверенных/национальных моделей)
- /regulirovanie-ii:uvedomlenie-polzovatelej-ii — обязательные уведомления пользователям об ИИ
- /regulirovanie-ii:gotovnost-k-zapusku-ii — чек-лист готовности AI-системы к запуску
- /regulirovanie-ii:politika-ispolzovaniya-ii — внутренняя политика использования ИИ
- /regulirovanie-ii:customize — точечно поправить профиль

Если AI-система обрабатывает ПДн — параллельно нужен настроенный personalnye-dannye
(use-case-triage, pdn-assessment). Этот плагин его не заменяет.
```

## Что НЕ делает

- Не настраивает `personalnye-dannye` — это отдельный плагин со своим cold-start
- Не проводит формальную «AI Impact Assessment» — см. CLAUDE.md плагина, раздел «Чего этот плагин
  не делает»

---

Проверки перед выдачей:
- [ ] Ключевая развилка «разработчик или пользователь по 243-ФЗ» задана и записана однозначно
- [ ] Если есть AI-системы с ПДн — явно отмечено, настроен ли `personalnye-dannye`
- [ ] Даты вступления в силу 243-ФЗ в резюме интервью соответствуют CLAUDE.md плагина, не взяты по
      памяти заново
