# /pererabotka-politiki

## Назначение

Черновик обновлённого текста ЛНА в ответ на уже установленное расхождение.
Не решает сам, что расходится, — это `poisk-probelov` (какие документы вообще
задеты) и `policy-diff` (что именно и с цитатой). Результат — проект, не
финальный документ.

## Контекст

Прочитай `~/.claude/plugins/config/claude-for-legal-ru/regulyatornyj-monitoring/CLAUDE.md`.
Файла нет или в нём `[ЗАПОЛНИТЬ]` — стоп: запусти
`/regulyatornyj-monitoring:cold-start-interview`.

## Pre-flight

- Таблица расхождений из `policy-diff` под рукой (пункт ЛНА ↔ норма акта ↔
  корзина), либо как минимум пункт из триажа `poisk-probelov`.
- Текущая редакция ЛНА доступна по пути из конфига или от пользователя.
- Реквизиты и дата вступления нового/изменившегося акта понятны.

Без цитаты и из `policy-diff`, и самой нормы правку не начинай — попроси
сначала дифф.

## Шаг 1. Загрузка текущего текста и триггера

```markdown
- Текущая редакция: [путь / название документа, версия]
- Триггер: [реквизиты акта] — [что именно изменилось] (действует с ДД.ММ.ГГГГ)
- Затронутые разделы (из policy-diff / poisk-probelov): [номера]
```

## Шаг 2. Черновик правки по разделу

Для каждого затронутого раздела:

```markdown
### Раздел [номер] — [название]

**Действующий текст:**
> [цитата]

**Предлагаемый текст:**
> [новая формулировка]

**Обоснование:** [норма акта], [что изменилось], действует с ДД.ММ.ГГГГ.

**Существенность:** 🔴 существенно — без правки документ расходится с актом
с даты вступления. / 🟡 уточняющее.
```

## Шаг 3. Redline

Правки — вычеркиванием и вставкой, не переписанным абзацем без пометок:

```markdown
# REDLINE: [ЛНА] v[X] → v[Y]

## Раздел [номер]

[текст] ~~вычеркнутое~~ **вставленное** [текст]
```

## Шаг 4. Чистая редакция

Отдельно — та же правка без вычёркиваний и вставок, готовая к финальному
тексту после согласования.

## Шаг 5. Ревью и утверждение

⚠ **Юрист обязан проверить** черновик перед публикацией. Это черновик, не
готовый документ.

1. Ревью юриста, ответственного за контур.
2. Утверждение руководителем практики / уполномоченным лицом.
3. Если документ трудовой и есть профсоюз — см. РФ-специфику ниже.
4. Официальное утверждение приказом.

## РФ-специфика

### ст. 74 ТК РФ — изменение существенных условий трудового договора

Если ЛНА трудовой (правила внутреннего распорядка, оплата, режим работы) и
правка меняет существенные условия трудового договора — нужна отдельная
процедура: уведомление работников за два месяца, согласие или увольнение по
п. 7 ч. 1 ст. 77 ТК РФ при отказе `[сверить дату и порядок по действующей
редакции ст. 74 перед применением]`.

→ Эта процедура — не часть черновика; передавай в `trudovoe-pravo:lna`.

### ст. 372 ТК РФ — учёт мнения профсоюза

Если профсоюз есть и документ входит в перечень, требующий учёта мнения:
запрос мнения перед утверждением, пять рабочих дней на ответ, при
несогласии — протокол разногласий.

→ Cross-ref `trudovoe-pravo:lna`.

## Формат вывода

Redline-файл + чистая редакция (Шаги 3–4) плюс короткий список действий
после утверждения:

```markdown
## После утверждения

- [ ] Приказ об утверждении новой редакции
- [ ] (если профсоюз) учёт мнения по ст. 372 ТК — выполнен
- [ ] (если касается работников) лист ознакомления подготовлен
- [ ] Старая редакция заменена, дата и версия зафиксированы
- [ ] Внутренний портал / реестр ЛНА обновлён
```

## Чего не делать

- Не публиковать черновик без ревью юриста и утверждения приказом.
- Не выдавать редлайн без обоснования нормой — каждая правка ссылается на
  статью и дату вступления.
- Не переписывать разделы, которых не касается триггер, «заодно, для
  свежести».
- Не запускать этот скилл без входа из `policy-diff` — самостоятельно решать,
  что расходится, он не должен.
