# /monitoring

Собирает, что появилось по watchlist, и отделяет проект от вступившего акта.

## Контекст

Прочитай `~/.claude/plugins/config/claude-for-legal-ru/regulyatornyj-monitoring/CLAUDE.md`.
Файла нет или `[ЗАПОЛНИТЬ]` — стоп: запусти cold-start.

## Шаг 1. Два разных портала

| Портал | Что там | Юридическое значение |
|---|---|---|
| `regulation.gov.ru` | проекты НПА, обсуждение, сводки замечаний | **не закон**. Можно планировать, нельзя применять |
| `publication.pravo.gov.ru` | официальное опубликование (ФЗ № 5-ФЗ) | текст, с которым сверяют вступление в силу |

Новость агрегатора, карточка консультанта, пересказ модели — помечай
`[вторичный источник]` и `[проверить по первоисточнику]`. Не поднимай их до статуса
опубликованного акта.

Федерального открытого API уровня Federal Register у этих порталов в плагине нет.
Работай так: пользователь дал ссылку / текст → разбери; иначе — открытый поиск по
названию органа и теме watchlist, каждый хит с тегом источника. Если поиск пустой —
скажи «лента пустая, не додумываю» и предложи вставить карточку.

## Шаг 2. Классификация

По порогам профиля:

- **вступивший ФЗ / постановление Правительства / указ**, который бьёт в «всегда
  смотреть» — 🔴;
- **проект** на regulation.gov.ru по той же теме — 🟡 плюс срок обсуждения
  (`sroki-obsuzhdeniya`);
- **письмо ведомства, методичка, обзор** — 📝, не «закон изменился»;
- вне watchlist — пропусти, не раздувай дайджест.

Не путай стадию: уведомление о разработке, текст проекта, окончательная редакция,
внесение в Госдуму, подписание, опубликование, вступление в силу — разные события.

## Шаг 3. Вступление в силу

Для опубликованного акта назови: дата опубликования на pravo.gov.ru; что написано в
самом акте про вступление; если молчит — общее правило официального опубликования
(для федеральных законов ориентир — **десять дней** после дня официального
опубликования, ФЗ № 5-ФЗ) `[общее правило сверить по ст. 6 ФЗ-5 и самому акту; многие
ФЗ пишут свою дату]`.

Не считай срок от новости «закон принят в третьем чтении».

## Формат вывода

```markdown
## Мониторинг: [период / тема]

### 🔴 Вступившее, бьёт в практику
**[орган] — [название]**. Опубликован [дата, pravo.gov.ru]. Вступает [дата].
Почему нам: [крючок из watchlist].
→ `/regulyatornyj-monitoring:policy-diff` против [политика]

### 🟡 Проекты
**[карточка regulation.gov.ru]**. Стадия: [проект]. Обсуждение до [дата].
→ `/regulyatornyj-monitoring:sroki-obsuzhdeniya`

### 📝 Письма и вторичное
[список с тегом источника]

**Пустых выводов из памяти модели нет.** Если хит только из знаний модели —
`[знания модели — проверить]`.
```

## Чего не делать

- Не выдавать проект за вступивший закон.
- Не подставлять дату третьего чтения как дату вступления.
- Не мониторить SEC/FTC/GDPR этим плагином.
- Не переписывать внутреннюю политику без `policy-diff` и решения человека.
