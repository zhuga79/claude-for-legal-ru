# /use-case-triage — триаж обработки ПДн

Быстрая сортировка: можно ли начинать обработку, что для этого обязательно, и куда идти дальше — по нормам ФЗ-152.

## Инструкции

1. **Загрузи профиль** `~/.claude/plugins/config/claude-for-legal-ru/personalnye-dannye/CLAUDE.md` (+ `company-profile.md`). Плейсхолдеры → останови, отправь на cold-start.
2. **Собери факты об обработке:** какие данные, о ком (субъекты), цель, кто оператор/обработчик, откуда данные, кому передаём, где хранятся/обрабатываются (РФ/за рубежом), автоматизировано ли решение.
3. **Прогони чек-лист триажа** (ниже). По каждому пункту — вывод + тег.
4. **Итог: 🟢 можно / 🟡 можно с условиями / 🔴 нельзя без [X]**, с конкретными обязательными действиями и ответственными.
5. **Закрой деревом следующих шагов** (составить согласие/политику → `pdn-assessment` для оценки → `poruchenie-review` если привлекаем обработчика).

## Чек-лист триажа (ФЗ-152)

1. **Это вообще ПДн?** Любая информация, относящаяся к прямо/косвенно определённому физлицу (ст. 3). Если обезличено необратимо — вне ФЗ-152 (но проверь реальную необратимость). `[решить]` при сомнении.
2. **Категория данных.** Обычные / **спецкатегории (ст. 10:** здоровье, раса, взгляды, интимная жизнь, судимость**) / биометрия (ст. 11)**. Спец/био → авто-🟡/🔴: нужны отдельные основания (ст. 10/11), для биометрической идентификации — ЕБС.
3. **Правовое основание (ст. 6 ч. 1).** Есть ли основание из закрытого перечня? Договор с субъектом (п. 5)? Закон (п. 2)? Иначе — **согласие (ст. 9)**. *Гибкого «законного интереса» как в GDPR в РФ нет.* Нет основания → 🔴.
4. **Согласие — если основание согласие.** Конкретное, информированное, с правом отзыва; для передачи третьим лицам и трансграничной — **отдельное** согласие; предзаполненные галочки недопустимы. Форма — при необходимости письменная (ст. 9 ч. 4).
5. **Уведомление РКН (ст. 22).** Нужно ли подать/обновить уведомление о намерении обрабатывать? *С 2022 исключения сужены.* `[проверить актуальные исключения — currency-watch]`.
6. **Локализация БД (ст. 18 ч. 5).** Данные граждан РФ — записываются/хранятся в базах на территории РФ? Иностранный сервис/облако → 🔴/🟡 до подтверждения локализации.
7. **Передачи и обработчики.** Передаём третьим лицам? Если привлекаем обработчика — нужно **поручение** (ст. 6 ч. 3) → маршрут на `poruchenie-review`. Передача третьим лицам как самостоятельным операторам — основание/согласие.
8. **Трансграничная передача (ст. 12).** За рубеж? Уведомление РКН ДО передачи; для стран без адекватной защиты — доп. условия. `[проверить порядок — currency-watch]`.
9. **Оценка / модель угроз.** Масштабная/рискованная обработка (спец, био, профилирование, большие объёмы) → предложи `pdn-assessment` (оценка вреда субъектам, ст. 18.1 ч. 5) и модель угроз (ПП-1119, ФСТЭК № 21).
10. **Конфликт с политикой.** Сверь с опубликованной политикой обработки (ст. 18.1 ч. 2 п. 2): покрывает ли она эту цель/категорию? Не покрывает → 🟡, нужно обновить политику (маршрут `policy-monitor`).

## Формат вывода

```markdown
[ШАПКА — по конфигу ## Выводы]

# Триаж обработки: [название]

**Итог:** 🟢 / 🟡 / 🔴
**Данные:** [категории], субъекты: [кто], основание: [ст. 6/9/10/11 …]

## Обязательно перед стартом
- [ ] [действие] — [норма] — ответственный [ФИО] `[решить]`/`[проверить]`

## Риски/открытые вопросы
- [пункт]

## Следующий шаг
[что и через какой скилл]
```

## Проверки перед выдачей
- [ ] Проверена категория (спец/био) и основание (закрытый перечень ст. 6)
- [ ] Проверены уведомление РКН, локализация, трансграничность (с тегами currency-watch)
- [ ] Для тем currency-watch выполнен веб-поиск актуальности
- [ ] Итог с конкретными действиями и ответственными, не «нужно посоветоваться с юристом»
