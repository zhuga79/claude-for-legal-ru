# Идентификация клиента

## Контекст дела

Прочитай `~/.claude/plugins/config/claude-for-legal-ru/protivodejstvie-otmyvaniyu/CLAUDE.md`. Файла
нет или в нём `[ЗАПОЛНИТЬ]` — стоп, направь на
`/protivodejstvie-otmyvaniyu:cold-start-interview`. Без настройки работает только cold-start.

Если включён режим `vedenie-del` и есть активное дело — досье клиента и решение о приёме на
обслуживание пиши в реестр дела.

## Назначение

Провести идентификацию клиента от приёма на обслуживание до текущего мониторинга отношений.

## Этапы

### Этап 1. Предварительная проверка до приёма на обслуживание

- Проверка личности / правоспособности
- Проверка по санкционным спискам (`/proverka-sanktsionnyh-spiskov`)
- Проверка по спискам публичных должностных лиц (`/proverka-pdl`)
- Проверка контрагента по открытым реестрам (ЕГРЮЛ/ЕГРИП, реестры недобросовестных лиц —
  применимо, если релевантно роду деятельности клиента)
- Поиск негативной информации в открытых источниках

### Этап 2. Идентификация

#### Для физических лиц (ст. 7 115-ФЗ)

Обязательные сведения:
- ФИО, дата рождения
- Гражданство
- Реквизиты документа, удостоверяющего личность
- Адрес регистрации (фактического проживания)
- ИНН (при наличии)
- СНИЛС
- Контактные данные

Документы: паспорт (РФ либо иностранный + миграционная карта/РВП/ВНЖ), свидетельство о постановке
на учёт в налоговом органе, иные — по требованиям ПВК организации.

#### Для юридических лиц

Обязательные сведения:
- Наименование, ИНН, ОГРН
- Адрес
- Учредительные документы
- Сведения о руководителе
- Бенефициарные владельцы (`/proverka-benefitsiara`)
- Структура управления (если применимо)
- Цели деятельности и предполагаемый характер деловых отношений

Документы: устав, актуальная выписка из ЕГРЮЛ, свидетельство о государственной регистрации,
решение о назначении руководителя, лицензии (если деятельность лицензируется), финансовая
отчётность (для изучения клиента).

### Этап 3. Изучение клиента

#### Категоризация риска

| Категория | Признаки | Объём проверки |
|---|---|---|
| **Низкий** | резидент РФ, прозрачная структура бизнеса, небольшие суммы, розничный клиент | упрощённая проверка |
| **Средний** | клиент по умолчанию, без признаков ниже или выше | стандартная проверка |
| **Повышенный** | см. признаки повышенного риска ниже | усиленная проверка |

#### Признаки повышенного риска

- клиент — публичное должностное лицо (иностранное, международной организации, российское);
- юридическое лицо из недружественной страны (контекст после 2022 года);
- сложная структура владения (каскад более 3 уровней);
- клиент с высоким состоянием (при значимых суммах операций);
- деятельность, интенсивно связанная с наличным оборотом;
- преобладание трансграничных операций;
- частая смена бенефициарных владельцев;
- негативная информация в открытых источниках;
- регулярные крупные операции с офшорными юрисдикциями;
- структура с использованием траста/номинальных директоров.

### Этап 4. Усиленная проверка для клиентов повышенного риска

- дополнительные документы: источник происхождения состояния, источник происхождения средств по
  конкретной операции, подтверждение налоговой добросовестности (для трансграничных ситуаций);
- личная встреча (для клиентов с высоким состоянием);
- утверждение приёма на обслуживание руководством организации;
- усиленный текущий мониторинг (более частые проверки);
- отчётность перед ответственным за ПОД/ФТ и руководством.

### Этап 5. Текущий мониторинг

- мониторинг операций (`/monitoring-operatsij`);
- периодический пересмотр досье: ежегодно для клиентов повышенного риска, раз в два года для
  среднего риска, по обстоятельствам для низкого;
- основания для внепланового пересмотра: изменение характера операций, новые бенефициарные
  владельцы, обращения регулятора, негативная информация, обновление списков, изменение категории
  риска клиента.

## Порядок работы

### Шаг 1. Начало приёма на обслуживание

```markdown
## Приём клиента на обслуживание: [имя/наименование]

- **Дата:** [ДД.ММ.ГГГГ]
- **Ответственный:** [пользователь]
- **Предварительная категория риска:** [низкий/средний/повышенный]
- **Запрошенные документы:**
  - [перечень]
```

### Шаг 2. Проверка документов

По каждому документу:
- **действительность** — срок действия, подлинность;
- **непротиворечивость** — сведения совпадают между документами;
- **полнота** — все обязательные поля заполнены;
- **соответствие требованиям регулятора** — Банк России или Росфинмониторинг, в зависимости от
  профиля организации.

### Шаг 3. Проверки

- проверка по санкционным спискам выполнена;
- проверка по спискам публичных должностных лиц выполнена;
- проверка по открытым реестрам недобросовестности выполнена (если применимо);
- бенефициарные владельцы установлены (для юридических лиц);
- поиск негативной информации выполнен.

### Шаг 4. Оценка риска

```markdown
## Оценка риска

| Фактор | Вес | Оценка | Взвешенная оценка |
|---|---|---|---|
| Тип клиента (физ./юр. лицо + статус) | 0,20 | [0–100] | ... |
| Страна / география | 0,20 | ... | ... |
| Характер деятельности | 0,15 | ... | ... |
| Ожидаемый характер операций | 0,15 | ... | ... |
| Бенефициарные владельцы (для юрлица) | 0,15 | ... | ... |
| Негативная информация | 0,10 | ... | ... |
| Ясность источника состояния/средств | 0,05 | ... | ... |
| Итого | | | [взвешенное среднее] |

**Категория риска:** низкий (< 30) / средний (30–70) / повышенный (> 70)
```

`[шкала весов и порогов — рабочий инструмент для организации собственной методики оценки риска;
115-ФЗ конкретной формулы не устанавливает — сверить с ПВК организации]`

### Шаг 5. Решение

**Приём на обслуживание.** Стандартный порядок, применение текущего мониторинга по категории
риска, планирование периодического пересмотра.

**Приём на обслуживание с условиями.** Требуется усиленная проверка до начала активных операций,
утверждение руководством.

**Отказ.**
- Документировать основание (ст. 7 ч. 5.2 115-ФЗ — обязательный отказ при невозможности
  идентификации клиента либо при возникновении подозрения, что целью является легализация доходов
  или финансирование терроризма);
- при повторных отказах в течение года — уведомление Росфинмониторинга;
- не раскрывать клиенту подробности причины отказа (запрет разглашения, ст. 4 115-ФЗ).

### Шаг 6. Документирование

Досье клиента должно содержать:
- все собранные документы (оригиналы либо заверенные копии);
- подписанную анкету идентификации;
- оценку риска;
- результаты проверки по спискам санкций/ПДЛ/открытых реестров;
- анализ бенефициарных владельцев (для юридических лиц);
- источник происхождения состояния/средств (для клиентов повышенного риска);
- утверждение руководством (для клиентов повышенного риска);
- обоснование решения о приёме на обслуживание;
- срок хранения: **5 лет с момента прекращения отношений с клиентом** (ст. 7 ч. 4 115-ФЗ)
  `[сверено 2026-08-26 — срок 5 лет подтверждён]`.

## Частые ошибки

**Критичные:**
- приём на обслуживание без завершённой идентификации — нарушение 115-ФЗ, риск санкций
  надзорного органа;
- бенефициарные владельцы юридического лица не установлены — нарушение;
- санкционная проверка не проведена — существенное нарушение комплаенса;
- неполная документация — риск при последующей проверке.

**Существенные:**
- периодический пересмотр пропущен или проведён с опозданием;
- категория риска занижена (типичная ошибка направления);
- усиленная проверка не запущена при наличии оснований;
- источник состояния/средств задокументирован недостаточно.

## Чего не делает

- Не выполняет фактический приём клиента на обслуживание — это операционная система организации.
- Не настраивает интеграцию комплаенс-системы — это задача ИТ и комплаенс-подразделения.
- Не разбирает жалобы и споры клиента — это клиентский сервис либо комплаенс-подразделение.

## Правовая основа

- ст. 7 115-ФЗ (обязанности по идентификации клиента)
- ст. 3 115-ФЗ (определение бенефициарного владельца)
- ст. 7 ч. 4 115-ФЗ (срок хранения досье)
- ст. 7 ч. 5.2 115-ФЗ (случаи обязательного отказа)
- Положение Банка России от 15.10.2015 № 499-П (для кредитных организаций) `[сверено 2026-08-27 —
  действует, с изменениями]`
- Постановление Правительства РФ № 667 (для остальных субъектов 115-ФЗ) `[проверить действующую
  редакцию]`
